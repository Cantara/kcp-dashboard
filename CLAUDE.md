# kcp-dashboard

Go TUI (Bubble Tea + Lip Gloss) that visualises KCP usage: reads `~/.kcp/usage.db`
(kcp-commands) and `~/.kcp/memory.db` (kcp-memory), read-only. Also ships `serve` — a
hook daemon on port 7734, a JVM-free drop-in for the kcp-commands Java daemon. Part of
the Cantara KCP ecosystem.

Read `knowledge.yaml` first — the canonical, agent-navigable map of this repo (units
`readme`/`main`/`view`/`db`, each with `intent` + `triggers`). Query it the standard KCP
way instead of grepping blind: `npx kcp-agent plan '<intent>' --manifest .`. It's
Ed25519-signed (`knowledge.yaml.sig`, auto-regenerated by `sign-kcp.yml` on push) —
never hand-edit the `.sig` file.

Shared governed-skill authoring conventions (PROFILE.md, `action_scope` as a firewall
rule) live in [kcp-skill](https://github.com/Cantara/kcp-skill), not here — e.g. use
its `release-and-tag` skill for cutting a release rather than inventing a local one.
This repo's own `skills/` holds procedures specific to kcp-dashboard only:
`update-knowledge-hashes` — fix a `content_hash` mismatch in `knowledge.yaml` after
editing `README.md`/`main.go`/`view.go`/`db.go`.

Gotchas:
- CI (`ci.yml`) runs `kcp validate`, deliberately not `kcp sign --update-hashes` — an
  un-updated `content_hash` after editing a tracked file fails the build late (green
  tests, red validate). See `skills/update-knowledge-hashes`.
- `serve` daemon mode (`main.go`, port 7734) is documented in release notes, not in
  README.md — don't assume the TUI is the only entry point.
